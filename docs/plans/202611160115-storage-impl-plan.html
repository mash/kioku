SQL と外部依存の境界
内部操作同じ SQL Tx に含めるもの外側の処理
Write / ReadWrite は writer 上の BEGIN IMMEDIATE。Read は reader の一貫した snapshot。ネストした Tx を作らない。各接続へ PRAGMA と比較関数を登録する。接続再作成時も同じ設定にする。
put / enqueue / claim認可・容量・件数・置換・期限・割当・Run。対象条件が変われば拒否。project ロック → 内容 GET/PUT → Tx。claim だけの保存状態を増やさない。
認証交換条件付き消費 + 発行。OAuth family 失効と同名 agent 失効も同じ Tx。provider 交換と本人確認は Tx の外。戻った後に対象行と本人を再検査する。
公開 / 親子 / 履歴Wiki の各参照更新、最終確定、View 結果+子終了、親の child_id と減算、監査と圧縮。入力・ZIP の検証は純粋関数。本文保存後に認可・世代・phase を再検査する。
usage / cleanupusage は INSERT ON CONFLICT DO NOTHING。初回値と org/user は以後変更しない。停止確認 → usage → provider cleanup → input_ready=0 → R2 DELETE → cleanup_complete=1。
commit 応答喪失対象キーで再照会する。確定済みなら状態を再利用し、不在なら条件を読み直す。即時の再実行は行わない。code 交換は秘密値を再現せず再ログイン。再接続不能は Fatal。

ロック順は生成用 gate → project gate → SQL Tx とする。SQL Tx を持って gate を待たない。provider の Start / Inspect / Stop / Cleanup は project gate と SQL Tx の外で呼ぶ。SaveRef は短い条件付き Tx だけを使う。

DB エラーは rollback、業務拒否は Declined、消費後の業務拒否だけ AppliedThenDeclined として commit する。Fosite は同じ Tx に束縛し、通常拒否を rollback、再利用拒否を commit に分ける。

T3 · 出力競合HTTP 出力到着 → Start 応答 → 停止通知 → 失敗確定直前に出力再読取。File 実行失敗は出力より失敗を優先。abort_reason / 認可喪失 / 検証失敗を優先する条件は U7（裁定）。

即時の自動リトライは 0 回とする。保留した処理は通知、worker 2 秒、reconcile 30 秒の契機で再評価する。周期ごとに同じ無進捗 job を内側の loop で再選択しない。ページ cursor の反復は一時失敗へ戻す。

provider / R2 の cleanup と GC は回数上限を設けず、成功か停止指示まで次の契機を待つ。これは永続的な外部障害では終了しない処理であり、τ だけの無限な内部実行とは区別する。停止待ち、0 件待ち、File 出力待ちの時間上限は E に従う。
