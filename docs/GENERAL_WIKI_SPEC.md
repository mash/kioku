# Kioku General Wiki の外部仕様

## アカウントの General

Kioku は各アカウントに専用のプロジェクトを1つ用意する。表示名は「General」、プロジェクトの slug は `general`。新規アカウントでは最初のサインイン時に、既存アカウントではサーバー起動時に利用できるようになる。再サインインや再起動で General が増えたり、namespace が変わったりすることはない。

General の namespace は、サインイン中のアカウントのプロジェクト一覧に表示された値をそのまま使う。ログイン名や表示名から namespace を組み立てない。同じ表示名や slug のプロジェクトが別にあっても、アカウント専用の General とは別のプロジェクトとして扱う。

## 会話での選択

新しい会話では、最初のメッセージから対象を選ぶ。すでに選択したプロジェクトは会話中に保持する。利用者が別のプロジェクトを指定した場合は、その指定を優先する。

| 状況 | 選択先 |
| --- | --- |
| 利用者が対象プロジェクトを指定した | 指定したプロジェクト |
| 会話ですでに対象を選択している | 選択済みのプロジェクト |
| 最初のメッセージから対象が一意に決まる | 一致したプロジェクト |
| 一致するプロジェクトがない、または複数あって決めきれない | サインイン中のアカウントの General |

対象が決めきれない場合、どのプロジェクトにするかを利用者に聞かず、General を選ぶ。General に公開済みのページがなくても選択できる。その場合は General を選んだことを伝える。

CLI では `kioku project list` で namespace を確認し、通常の `kioku -n NAMESPACE session select` で選択する。コネクターでは `projects_list` に表示された namespace を使う。

## アクセスと管理

- General は本人のアカウント専用。別のアカウントへの招待と所有権移譲はできない。
- コネクターから General を利用するには、接続時に General へのアクセスを許可する。対象の Wiki へのアクセスがない場合は、同じアカウントで対象を許可して再接続するよう案内する。別のプロジェクトへ読み書きを切り替えない。
- General 単独の削除は HTTP 409 で拒否される。アカウントを削除すると、その General と保存済みの内容も削除される。
- 現行の CLI と API には、プロジェクトの表示名または namespace を変更する操作はない。
