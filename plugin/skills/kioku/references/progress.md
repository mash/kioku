# 進捗と根拠を読む

remote mode では [remote.md](remote.md) の読み書き手順を使う。
本文の `kioku` は [SKILL.md](../SKILL.md) で定義した CLI（コマンドラインの操作ツール）のパスを指す。
CLI の呼び出しは `kioku -C "$P"` で始める。

## 作業中の参照と送信

複数段階の作業を始める前、マイルストーン完了時、障害・方針・次の手が変わった時に、既存の進捗文書と判断の根拠を確認する。

1. 取得済みの Wiki の index と関連する進捗・意思決定ページを読む。
   新しい内容が必要な場合は pull する。未生成の資料や別会話の状況は確認できる範囲で答える。
   確認できない内容は未確認とし、古いコピーを最新と呼ばない。
2. ユーザーが共有を許可した進捗文書を作成・更新した場合は、[capture.md](capture.md) の手順で送信する。
   Claude が原文の全文を読み、本文と原本の HTTPS（暗号化した Web 通信）URL（資料のアドレス）を送信する。
   Kioku への送信だけを目的とする会話要約、作業イベント、失敗の記録は作らない。
3. 原本の HTTPS URL がなければ送信せず、未保存と伝える。
   URL を捏造せず、URL を得るためだけに文書を公開しない。
   利用者の目標や他のメンバーの状況を、この会話だけの観測で上書きしない。
4. ユーザーが即時生成を依頼し、local mode の書き込み権限があれば生成する。
   `kioku -C "$P" generate --wait` の後に status と取得した Wiki を確認する。
   実際に生成した内容だけを報告する。remote mode は定期生成を待つ。

「今どこ？」には、保存済みの文書と原本を根拠に答える。
受付済みの原資料と公開済み Wiki を区別する。
ローカル state.json・HTML（Web ページの記法）・history ディレクトリを進捗の正本にしない。

## 表示と公開

認証済み Kioku Web ビューアーは open で開く。maps/graph.json は知識関係図であり、専用の進捗ダッシュボードではない。

必要なら、この会話内の図や一時 HTML を根拠から作る。
表示用のコピーであり、次回の正本にしない。
HTML は文字列をエスケープし、HTTP（Web 通信の規約）と HTTPS 以外の出典リンクを入れない。
外部スクリプトも入れない。表示を確認できない場合は未確認と伝える。

ユーザーが許可した Artifact／Sites の公開先とツールがあれば、同じ公開先を更新できる。
公開した文書を Kioku に送信する場合も capture.md の手順を使う。
承認待ち、本番操作、外部送信への返事がないことを承認と扱わない。
