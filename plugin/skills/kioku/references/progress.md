# 進捗と根拠を読む

remote mode では [remote.md](remote.md) の読み書き手順を使う。
本文の `kioku` は [SKILL.md](../SKILL.md) で定義した CLI のパスを指す。CLI の呼び出しは `kioku -C "$P"` で始める。

## 作業中の参照と投入

複数段階の作業を始める前、マイルストーン完了時、障害・方針・次の手が変わった時に、既存の進捗文書と判断の根拠を確認する。

1. 取得済みの Wiki の index と関連する進捗・意思決定ページを読む。新しい内容が必要な場合は pull する。未生成の資料や別会話の状況を確認できない場合は未確認とし、古いコピーを最新と呼ばない。
2. 今回の作業で、共有を許可された進捗文書そのものを作成・更新した場合は、その原本を [capture.md](capture.md) の手順で投入する。取得できる文書なら URL、取得できない文書なら本文と原本 URL を渡す。Kioku へ送るためだけの会話要約、作業イベント、失敗メタデータは作らない。
3. 原本 URL がなければ投入を保留する。URL を捏造したり、取得するためだけに文書を公開したりしない。利用者の目標や他のメンバーの状況を、この会話だけの観測で上書きしない。
4. 即時反映を依頼された場合、local mode の書き込み権限があれば `kioku -C "$P" generate --wait` を実行する。その後 status と取得した Wiki を確認し、実際に反映した内容だけを報告する。remote mode は定期生成を待つ。

「今どこ？」には、保存済みの文書とその原本を根拠に答える。受付済みの原資料と公開済み Wiki を区別する。取得失敗を尋ねられた場合は wiki/log.md を読む。ローカル state.json・HTML・history ディレクトリを進捗の正本にしない。

## 表示と公開

認証済み Kioku Web ビューアーは open で開く。maps/graph.json は知識関係図であり、専用の進捗ダッシュボードではない。

必要なら、この会話内の図や一時 HTML を根拠から作る。表示用のコピーであり、次回の正本にしない。HTML は文字列をエスケープし、HTTP(S) 以外の出典リンクや外部スクリプトを入れない。表示を確認できない場合は未確認と伝える。

既に許可された Artifact／Sites の公開先とツールがある場合は、同じ公開先を更新できる。公開した文書を Kioku に投入する場合も capture の原資料の手順を使う。承認待ち、本番操作、外部送信への返事がないことを承認と扱わない。
